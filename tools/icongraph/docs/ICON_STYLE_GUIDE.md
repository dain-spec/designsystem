## P02 · 1.1  문서 범위 — 3가지 스타일

`배치 4280, 120`

이 문서는 세 가지 아이콘 스타일을 하나로 다룬다. 셋은 **같은 캔버스·같은 Key shape·같은 Radius** 위에서 그려지고, 표현 방식만 다르다.

| 스타일 | 표현 | 쓰이는 곳 | 네이밍 |
|---|---|---|---|
| **Line** | 선(stroke). 기본 두께 1.5 | UI 기본. 목록·버튼·내비게이션 | `ic_의미` · `_thin` · `_thick` |
| **Fill** | 단색 면 | 선택 상태, 강조가 필요한 자리 | `ic_의미_fill` |
| **Multicolor** | 다색 면 3단 레이어 | 대시보드·안내·빈 화면 등 설명이 필요한 자리 | `ic_의미_flat` |

### 세 스타일이 공유하는 것

| 항목 | 값 | 근거 |
|---|---|---|
| 캔버스 | 24 × 24 | 두 가이드 모두 동일 |
| Key shape | square 18×18 · rect 20×16 · rect 16×20 · circle 20×20 | Multicolor 36 / 57종이 4종에 일치 |
| Radius | 면 최소변 × 0.19 | 변 18 → 3.5 · 변 16 → 3.0 (양쪽 모두) |
| Size | 14 · 18 · 24 · 32 · 40 | Figma · 가이드 제작 진행중 › Guide |
| 두께 기준값 | 1.5 | Line = stroke 1.5 / Fill·Multicolor = 최소 면 두께 1.5 |

### 갈리는 것

| 항목 | Line | Fill | Multicolor |
|---|---|---|---|
| 두께 | stroke 1 / 1.5 / 2, 정렬 Center | 면 두께 ≥ 1.5 | 면 두께 ≥ 1.5 |
| 색 | 단색 | 단색 | 7 family × 5 step |
| 레이어 | 단일 | 단일 | Base → Accent → Detail → Badge |
| 제작 | outline stroke → Union → Flatten | Union/Subtract → Flatten | **Subtract 금지** → Flatten |
| 접미사 | `_thin` `_thick` | `_fill` | `_flat` · 이모지 `_face` |

## P03 · 1.2  스타일 선택 기준

`배치 120, 1360`

어떤 스타일로 그릴지는 **아이콘이 놓이는 자리**가 정한다. 같은 개념을 세 스타일로 모두 만들 필요는 없다.

| 상황 | 스타일 | 이유 |
|---|---|---|
| 목록·버튼·내비게이션 등 반복되는 UI | **Line** | 면이 많으면 화면이 무거워진다 |
| 같은 아이콘의 선택·활성 상태 | **Fill** | Line 과 짝을 이뤄 상태를 구분 |
| 대시보드 카드·안내 문구·빈 화면 | **Multicolor** | 설명을 돕는 자리. 개수가 적어야 효과가 있다 |
| 16px 이하로 축소되는 자리 | **Line** | Multicolor 는 레이어가 뭉개진다 |
| 같은 화면에 8개 이상 나열 | **Line** 또는 **Fill** | Multicolor 가 많으면 시선이 분산된다 |

> **[확인 필요]** 위 기준은 두 가이드의 용례에서 역산한 제안이다. 실제 운영 기준이 다르다면 이 표를 먼저 확정해야 한다.

### 짝을 맞춰야 하는 경우

Line 과 Fill 은 **같은 실루엣**을 공유해야 한다. 상태가 바뀔 때 형태가 달라 보이면 다른 아이콘으로 읽힌다. Multicolor 는 독립적으로 그려도 된다.

## P05 · 2.1  그리드와 패딩

`배치 4280, 1360`

> 아이콘을 그리기위한 기본 사이즈를 24px로 잡아서 그리드에 맞춰 제작합니다.

<sub>출처 — Figma · 가이드 제작 진행중 › Guide</sub>

### 라이브 영역과 패딩

캔버스 24 안에서 형태가 들어가는 영역이 라이브 영역이고, 그 바깥이 패딩이다. 패딩은 아이콘이 다른 요소와 붙지 않게 하는 최소 여백이므로 침범하지 않는다.

| 라이브 영역 | 좌표 | 패딩 | 쓰는 형태 | Multicolor 사용 |
|---|---|---|---|---|
| **20 × 20** | `2 → 22` | 2 | 원형·와이드·유기적 실루엣 | 12종 |
| **18 × 18** | `3 → 21` | 3 | 사각 컨테이너 | 23종 |
| 자유 실루엣 | `1 → 23` | 1 | 핀·카트처럼 한쪽으로 뻗는 형태 | 22종 |

### 배지 예외 — Multicolor

> 배지가 붙을 때만 라이브 영역을 넘길 수 있다. 실제 세트의 최대 확장은 `x 22.13` — 즉 캔버스 경계에서 최소 `1.8` 의 여백은 항상 남긴다.

### 도해

2단 구성 · 각 480 × 480 · 24분할 그리드 위에 아이콘 배치 · 라이브 영역은 점선 `#D2384F`

## P06 · 2.2  Key shape

`배치 120, 2600`

> Keyline shape를 가이드 라인으로 사용하여 아이콘에서 일관된 비율을 유지합니다. 아이콘의 시각적 균형을 맞추기 위해 keyline을 기준으로 일부 요소가 살짝 길거나 짧게 조정이 가능합니다.

<sub>출처 — Figma · 가이드 제작 진행중 › Guide</sub>

### 4종

| Key shape | Multicolor 사용 | 예 |
|---|---|---|
| **square 18×18** | 18종 | `box`, `calcu`, `dashboard`, `doc_aicheck` |
| **rect 20×16** | 6종 | `browser`, `card`, `card_money`, `contract` |
| **rect 16×20** | 2종 | `guide`, `receipt` |
| **circle 20×20** | 10종 | `arrow_left`, `arrow_right`, `emoji_cry_face`, `emoji_heart_face` |

Monochrome 가이드가 정의한 4종이 Multicolor 에도 그대로 나타난다 — **36 / 57종 (63%)**. 두 스타일이 같은 골격을 쓴다는 근거이며, 이 문서를 하나로 합친 이유이기도 하다.

### 자유 실루엣

나머지 21종은 4종에 맞지 않는 오브젝트 형태다. 이 경우 Key shape 대신 **시각 무게**를 4종에 맞춘다 — 나란히 놓았을 때 같은 크기로 보이면 된다.

`boxes` `cart` `doc_folder` `factory` `folder` `goverment` `goverment_money` `graph_growth` `insurance` `map` `map_pin` `passbook_arrow` `pc_down` `pc_remote` `pin` `place` `process` `shop_bag` `siren` `truck` `user_money`

## P15 · 3.3  Multicolor — 컬러 사용 규칙

`배치 120, 6320`

| 규칙 | 내용 |
|---|---|
| **아이콘 1개 = 주 hue 1개 + white** | Base 와 Deep 은 같은 family 에서 가져온다 |
| **두 번째 hue 는 신호에만** | 배지, 경고 램프, 상태 점 등 '여기를 보라'는 요소에 한정. `ic_siren_flat`(grey+coral), `ic_goverment_money_flat`(navy+teal) 이 기준 사례 |

## P19 · 3.4  Do · Don't

`배치 2200, 7560`

세 스타일 공통 원칙이다. Line 예시로 그려져 있으나 Fill · Multicolor 에도 같이 적용된다.

| ✓ Do | ✕ Don't |
|---|---|
| 선 끝을 둥글게 표현 | 선 끝을 뾰족하거나 각지게 표현하지 않음 |
| 일관된 선 굵기 사용 | 다양한 굵기의 선을 함께 사용하지 않음 |
| 요소들의 정렬은 눈으로 봤을 때 기준으로 맞춤 | 수치로만 정렬하지 않음 |

<sub>출처 — Figma · 가이드 제작 진행중 › Guide › Guide</sub>

### 스타일별 추가

| 스타일 | ✓ Do | ✕ Don't |
|---|---|---|
| Line | 선 끝·꺾임을 둥글게 | 두께를 섞어 쓰기 |
| Fill | 짝이 되는 Line 과 같은 실루엣 | Fill 단독 아이콘 만들기 |
| Multicolor | 주 hue 1개 + white | opacity 로 중간 톤 만들기 · 도형 Subtract |

### 정렬에 대하여

**수치로만 정렬하지 않는다.** 원과 사각형을 같은 좌표에 두면 원이 작아 보인다. Key shape 4종이 서로 다른 크기인 이유도 같다 — 눈으로 봤을 때 같은 무게가 되도록 맞춘다.

## P20 · 4.1  제작방법 — 스타일별 3플로우

`배치 4280, 7560`

> 아이콘 오브젝트의 원형보존 및 추후 변형의 용의성을 위해 원본과 배포하는 영역은 분리하여 보존합니다. 아이콘은 outline stroke하여 채워진 도형으로 배포되어야 추후 SVG에서 변형이 되지 않습니다.

### 3플로우 대조

|  | Line | Fill | Multicolor |
|---|---|---|---|
| 1 | 24 가이드에 맞춰 제작 | 24 가이드에 맞춰 제작 | 24 가이드에 맞춰 제작 |

> **Multicolor 는 정반대다.** 플랫아이콘은 도형 subtract 하지 않습니다. (배경색 영향 받지 않게) Icon과 형태 똑같이 사용해주세요. (예: 원 표시)

<sub>출처 — Figma · 가이드 제작 진행중 › Guide › 알림</sub>

Fill 은 Subtract 로 구멍을 파도 되지만, Multicolor 에서 같은 방식을 쓰면 그 구멍으로 배경색이 비친다. Multicolor 의 '구멍'은 배경을 파는 것이 아니라 **그 자리에 다른 색 면을 얹어** 표현한다.

## P21 · 4.2  Export 규칙

`배치 120, 8800`

Figma 에서 뽑은 SVG 를 그대로 커밋하지 않는다. 아래 형태로 정리한 뒤 저장한다.

### Multicolor

```svg
<svg width="24" height="24" viewBox="0 0 24 24" fill="none" xmlns="http://www.w3.org/2000/svg">
  <path d="…" fill="#6DACFF"/>   <!-- L1 Base -->
  <path d="…" fill="#1772E9"/>   <!-- L2 Accent -->
  <path d="…" fill="white"/>     <!-- L3 Detail -->
</svg>
```

|  | 내용 |
|---|---|
| **제거** | `id` / `class` 잔여물, 빈 `<g>`, 사용하지 않는 `clipPath`, `data-*` |
| **금지** | `stroke`, `opacity`, `filter`, `style` 속성 |
| **조건부 허용** | `mask` 는 도넛·파이 형태에만. Figma 자동 생성 id(`mask0_16817_1404`)는 인라인 시 충돌하므로 아이콘 id 를 포함한 이름으로 바꾼다 |
| **좌표** | 소수점 4자리까지. 그 이상은 잘라낸다 |
| **구멍** | `fill-rule="evenodd"` 로 배경이 비치는 구멍을 만들지 않는다 — 그 자리에 다른 색 면을 얹는다 |

### 검증

- `nan` · `Infinity` 등 잘못된 좌표가 없는지 — 유효하지 않은 명령이 있으면 브라우저가 그 지점에서 렌더링을 멈춘다
- 24px 로 축소해 실제로 보이는지

> **[확인 필요]** Line · Fill 의 Export 규칙은 Figma 가이드에 없다. outline stroke 후 면으로 배포한다는 원칙만 있으므로, 나머지 정리 규칙을 Multicolor 와 동일하게 적용할지 결정이 필요하다.
